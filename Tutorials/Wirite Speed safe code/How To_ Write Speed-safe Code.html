How To: Write Speed-safe Code

Being a true programming language, Jamagic runs everything as fast as it can. Of course, with the diversity of the modern PC, you need to make sure that no-one is left behind by the action.

Used in Clickteam Jamagic tutorials section with permission. Original version here.

All code examples in this "How To" can be found as a Jamagic project in this ZIP archive.

The Amazing Cube Enlightens Us

You might at first be wondering exactly what I mean. Don't worry; people are always telling me what 'wonderful' communications skills I have. Try out the following example: 

Example 01 - The Amazing Cube
// Before running this, remove the default window creation code from "Project Settings"
// We're just going to use plain, vanilla software mode.
// This should make any speed differences more apparent.
SetDisplayInterface(Display.SOFTWARE);
// Create and prepare a window
winCube=New Window(System.GetScreenWidth()/2,System.GetScreenHeight()/2,,,,,"Initializing");
winCube.SetAutoRefresh(FALSE);
winCube.SetAutoClose(FALSE);
// Create a world
wrlCube=New World();
// Create a surface to make a texture to make a material
srfYellow=New Surface(32, 32, 8);
srfYellow.CLEAR(0xFFFF00, 0x000000);
texCube=New Texture(wrlCube, srfYellow);
matCube=New Material(wrlCube, texCube, 0xFFFF00, "CubeMaterial");
// Create a cube (it wouldn't be very amazing if it didn't exist)
objCube=wrlCube.CreateBrick(16,16,16);
objCube.ApplyMaterial(matCube, TRUE);
objCube.SetFlat(TRUE);
// Create a camera so that we can actually see all this 3D trickery
camCube=New Camera(wrlCube, winCube);
camCube.MoveBack(64);
// Light our brick so that we can make out the sides
wrlCube.SetGouraud(TRUE);
// Prepare some way to stop the demo (just press a key or close the window)
booRun=TRUE;
winCube.OnKeyDown=StopRunning;
winCube.OnClose=StopRunning;
While(booRun)
{
	// Spin the cube a bit
	objCube.AddAngle(0.03,0.02,0.01);
	// Show the frames per second
	winCube.SetText("The Amazing Cube - "+Round(camCube.GetSpeed())+" FPS");
	// Update the display
	Refresh();
}
End();
Function StopRunning()
{
	booRun=FALSE;
}

It's a spinning cube. Thrilling huh? No? Well, try running it on a different specification machine.

If you don't have another machine to hand, or don't want to go through all the fuss of transferring your project(s), you can simulate a slower machine by setting "Processor usage" to a lower figure in "Project > Settings > Run". This won't directly affect your 3D card however, so if you're using a hardware mode then you may not notice much difference.
What's more, because Windows gives any window over which the mouse is moving 100% attention, you can set this value right down and compare when the mouse is and is not moving.

You'll no doubt find that the cube spins at a different speed (if not, then pay attention and try different specification computers). While our happy little cube may not really matter too much, imagine that that was a target in a shooting game, or the ball in a sports game. Someone on a ninja 2GHz beast with a GeForce4Ti would never be able to hit it, while someone hobbling along in software mode on their 500MHz Celeron (yes, I'm the latter) would find it pitifully easy. You need to control the speed so that both can have the same gaming challenge (if not the same silky smooth framerates).

Don't Run When You Must Walk

The simple solution to this problem is to limit the maximum speed at which the code can run (this is by no means the best solution, which I will get onto a little later, but it is very well known so deserves mention).

Of course, the main problem with this method is that the GeForce 4 owner will find his machine 'wound down' to the same performance as that Celeron (the other problem being the challenge of finding a suitable framerate at which to fix the program).

The principle is quite simple - you time how long it takes for your program to execute it's main loop and, if this too short, wait for the remaining time.

Modify example 1 by replacing the main 'While' loop with this one (changes marked with '←'): 

Example 02 - The Amazing Cube Strikes Back
// IMPORTANT: These are just the changes to make to Example 1
// Take a measurement of the current time (in milliseconds)
intTimeLastLoop=System.GetElapsedTime(); ←
While(booRun)
{
	// Spin the cube a bit
	objCube.AddAngle(0.03,0.02,0.01);
	// Show the frames per second
	winCube.SetText("The Amazing Cube II - "+Round(camCube.GetSpeed())+" FPS");
	// Update the display
	Refresh();
	// If this frame has taken less than 50ms (equal to 20FPS) then wait
	While((System.GetElapsedTime()-intTimeLastLoop)<50); ←
	// Update time measurement
	intTimeLastLoop=System.GetElapsedTime(); ←
}

Try this on some different computers (or at some different CPU usages) and you'll find that it should never exceed 20FPS. On the other hand, try it out on a very slow computer and the cube will spin much too slowly because the code only corrects for computers that are too fast.

There isn't really a case where this is the 'right' method to use (only if you want a very low fixed framerate), so I won't go into too much detail. The time per frame in milliseconds is quite simply 1000 divided by the maximum framerate you want. So 20FPS gives 1000/20 = 50ms.

Delta and differentials

So, what is the 'best' way to do speed-safe code? It's really actually quite easy. In fact, it doesn't even require much mathematics (so don't let the subtitle scare you).

Scary Maths Bit! If you want to know, the maths behind this is actually quite simple. It's based on the equation Δx = Δt*(Δx/Δt), where Δx is the difference in distance and Δt is the difference in time. Obviously both sides of that equation are the same thing - Δx - because Δx divided by Δt multiplied by Δt is just Δx. The equation shows how to work out Δx (the difference in distance - how much you should move your object by this frame) from Δt (which you can measure, or use 1/framerate) and Δx/Δt (the amount you want your object to move per second).

What you want to do is to let Jamagic run as fast as possible, but adjust the amount that is done each frame so that everything happens at the right speed. This is great because it means that fast computers will run the program really smoothly and slow computers in Jerk-O-Vision™. Basically every computer can do its best without upsetting the action - just like a proper commercial game.

It can also make your calculations for when things happen a lot easier. Take our Amazing Cube. Every frame it rotates by (0.03, 0.02, 0.01) - but how much is that? It depends on the framerate. It can be quite hard to relate to 0.03 because it's quite small and you're considering how much it rotates in a tiny fraction of a second.

What this 'best' method does is consider how long each frame is. You can either time this with System.GetElapsedTime() like for limiting the framerate or, because it's easier for 3D programs, use Camera.GetSpeed(). Camera.GetSpeed() returns the framerate, which is the inverse of the frame time. If you're running at two frames per second, then each frame must last half a second. In other words, 2FPS = 1/2s. This means that 1.0/Camera.GetSpeed() is the length of an average frame (in seconds).

This makes things a lot easier, because you can now specify all your movement in terms of distance per second. All you have to do is work out the length of a frame and multiply. If you want to move something at a rate of one unit per second, then you just move it by the length of the frame each frame. After one second the sum of the lengths of all the frames will be...one second, so your object will have moved one unit. If you want to move it at two units per second you just double the amount you move it each frame. For rotation, just multiply by 2π (there are 2π radians in a full circle, so if you rotate at 2π radians/second you do one rotation per second).

To save working out 1/Camera.GetSpeed() each time you can just do it at the start of the frame. I call it the 'speed coefficient', because it's the number you multiply your speed by. Let's see what this does to our cube (again, replace the While loop from example one - changes marked with '←'): 

Example 03 - Return of the Amazing Cube
// IMPORTANT: These are just the changes to make to Example 1
// Prepare the speed coefficient. It should be a float because it will
// be a small fraction (each frame is only a little bit of a second).
// 0.05 is a fair guess as a start - equal to 20FPS
fltSpdCoeff=0.05; ←
While(booRun)
{
	// At first (or if it goes realllly slow), the camera gives silly FPS readings
	// We must ignore an FPS of zero, because you can't divide by zero
	If(camCube.GetSpeed()>0) ←
	{ ←
		fltSpdCoeff=1.0/camCube.GetSpeed(); // Use 1.0 to force decimals ←
	} ←
	// Spin the cube a bit - remember to include the speed coefficient!
	objCube.AddAngle(3*fltSpdCoeff,2*fltSpdCoeff,fltSpdCoeff); ←
	// Show the frames per second
	winCube.SetText("The Amazing Cube III - "+Round(camCube.GetSpeed())+" FPS");
	// Update the display
	Refresh();
}

The cube should be spinning as smoothly as it did in example 1. However, if you try a slower machine (or lower CPU usage) you should find that it still spins at the same speed; it's just jerkier. Hooray! Now all the GeForce4 and Celeron owners the world over can unite in peace, because they can all enjoy the same speed of spinning cube yet use their computers to their maximum capability!

Rocket Science

Rotating cubes are very nice, but what about something a bit more complex? Because the speed coefficient is precalculated each frame, it's very simple. Just think about all you motions in terms of distance (either world units, pixels or radians depending on what you're doing) per second. You can even control other things with the time coefficient, like fades or animations (in the latter case, animation frames per second).

If you're doing something outside of the 3D engine then you won't be able to use Camera.GetSpeed() and need to instead measure the frame time with System.GetElapsedTime().

Here is a cut-down speed-safe version of my Object Oriented Fireworks demo to show this applied to 2D graphics (the original used the limiting version):

Example 04 - It's Not Rocket Science, But This Is
// Quite a few things have been removed to keep this example small, like most of the comments.
// Again, remember to remove the default window creation code
// Checking for DirectDraw first keeps Linux/Mac/WinNT users happy
If(Display.IsDisplayInterfaceAvailable(Display.SOFTWARE_DIRECTDRAW))
{
	SetDisplayInterface(Display.SOFTWARE_DIRECTDRAW);
}
Else
{
	SetDisplayInterface(Display.SOFTWARE);
}
// Miscellaneous Init
intScreenWidth = System.GetScreenWidth();
intScreenHeight = System.GetScreenHeight();
Math.SetRandom(System.GetElapsedTime());
// Create window
winMain = New Window(intScreenWidth, intScreenHeight,,,,,"Rocket Science");
winMain.SetAutoRefresh(FALSE);
winMain.SetFullScreenMode();
// srfMain = New Surface(); // for IntelliSense
srfMain = winMain.GetSurface();
srfMain.SetAutoRefresh(FALSE);
// Create objects
For(intLoop=0;intLoop<32;intLoop++)
{
	This.objRocket[intLoop] = New Firework();
	This.booRocketExists[intLoop] = TRUE;
}
intRocketCount = 32;
objFire[0] = New Fireparticle(objRocket[0]);
objFire[0].intX = -1;
booFireExists[0] = TRUE;
For(intLoop=1;intLoop<1024;intLoop++){booFireExists[intLoop]=FALSE;}
booRunMainLoop = TRUE;
winMain.OnKeyDown = HandleKeypress;
// Speed-safe variables
fltSpeedConstant = 0.05; // the speed constant
intTimeLastLoop = System.GetElapsedTime() - 1; // used to time loops

While(booRunMainLoop)
{
	// Prepare the speed constant
	// We don't need 1.0/ because this isn't frames per second
	// Because System.GetElapsedTime() uses milliseconds, divide by 1000.0
	fltSpeedConstant = (System.GetElapsedTime()-intTimeLastLoop)/1000.0;
	// Update the variable used to time loops
	intTimeLastLoop = System.GetElapsedTime();
	// When we use the speed constant in this project, we use a speed of 10.
	// This makes it run at about the same speed as it did with the old limiting
	// method.
	
	// CREATION
	While (((Math.Random(7) < 3) || (intRocketCount < 8)) && (intRocketCount < 24))
	{
		intRocketSlot = 0;
		For(intLoop=31;intLoop>=0;intLoop--)
		{
			If(!booRocketExists[intLoop]){intRocketSlot=intLoop;}
		}
		objRocket[intRocketSlot] = New Firework();
		booRocketExists[intRocketSlot] = TRUE;
		intRocketCount++;
	}
	
	// DISPLAY
	srfMain.EraseRect();
	srfMain.Lock();
	DisableEvents();
	For(intLoop=0;intLoop<32;intLoop++)
	{
		If(booRocketExists[intLoop]){objRocket[intLoop].DrawSelf();}
	}
	For(intLoop=0;intLoop<1024;intLoop++)
	{
		If(booFireExists[intLoop]){objFire[intLoop].DrawSelf();}
	}
	EnableEvents();
	srfMain.Unlock();
	srfMain.Refresh();
	
	// MOVEMENT
	// This has had to change a little; now we must pass the speed constant
	// to our objects. This is because these particular objects calculate their
	// distances to add internally.
	For(intLoop=0;intLoop<32;intLoop++)
	{
		If(booRocketExists[intLoop]){objRocket[intLoop].MoveSelf(fltSpeedConstant);}
	}
	For(intLoop=0;intLoop<1024;intLoop++)
	{
		If(booFireExists[intLoop]){objFire[intLoop].MoveSelf(fltSpeedConstant);}
	}
	
	// EXPIRATION
	For(intLoop=0;intLoop<32;intLoop++)
	{
		If(booRocketExists[intLoop])
		{
			If(TestFireworkLife(objRocket[intLoop]))
			{
				intExplosionMagnitude = Math.Random(24) + 8;
				For(intLoop2=1;intLoop2<=intExplosionMagnitude;intLoop2++)
				{
					intFireSlot = -1;
					booKeepLookingForSlot = TRUE;
					intLoop3 = 1023;
					While((intLoop3 >= 0) && (booKeepLookingForSlot))
					{
						If(!booFireExists[intLoop3])
						{
							intFireSlot=intLoop3;
							booKeepLookingForSlot = FALSE;
						}
						intLoop3--;
					}
					If(intFireSlot != -1)
					{
// (the below line's indenting has been changed to make it fit in your browser window)
				objFire[intFireSlot] = New Fireparticle(objRocket[intLoop]);
						booFireExists[intFireSlot] = TRUE;
					}
				}
				Delete objRocket[intLoop];
				booRocketExists[intLoop] = FALSE;
				intRocketCount--;
			}
		}
	}
	For(intLoop=0;intLoop<1024;intLoop++)
	{
		If(booFireExists[intLoop])
		{
			If(TestFireparticleLife(objFire[intLoop]))
			{
				Delete objFire[intLoop];
				booFireExists[intLoop] = FALSE;
			}
		}
	}
}
End();

//// FUNCTIONS
Function LookupHueColourR(fltHue)
{
	Return (Cos(fltHue*(Pi()/1.5)))*255;
}
Function LookupHueColourG(fltHue)
{
	Return (Cos(fltHue*(Pi()/1.5)-(Pi()/1.5)))*255;
}
Function LookupHueColourB(fltHue)
{
	Return (Cos(fltHue*(Pi()/1.5)+(Pi()/1.5)))*255;
}

Function HandleKeypress(winWindow, intKey)
{
	If(Program.GetChar(intKey)==" "){booRunMainLoop = FALSE;}
}

Function TestFireworkLife(objFireworkToTest)
{
	booExplode = FALSE;
	If(objFireworkToTest.intFuseLength < 0){booExplode = TRUE;}
	If(objFireworkToTest.intX < 0){booExplode = TRUE;}
	If(objFireworkToTest.intX > intScreenWidth){booExplode = TRUE;}
	If(objFireworkToTest.intY > intScreenHeight){booExplode = TRUE;}
	Return booExplode;
}

Function TestFireparticleLife(objFireparticleToTest)
{
	Return (objFireparticleToTest.fltBrightness < 0.1);
}

//// CLASSES
Function Firework()
{
	This.intX = Math.Random(intScreenWidth);
	This.intY = intScreenHeight - 1;
	This.intXspeed = Math.Random(9) - 4;
	intLaunchSpeed = intScreenHeight/32;
	This.intYspeed = -(Math.Random(intLaunchSpeed+1) + intLaunchSpeed);
	This.fltHue = 3 * Math.Random();
	This.intFuseLength = Math.Random(32) + 16;
	This.DrawSelf = Firework_DrawSelf;
	This.MoveSelf = Firework_MoveSelf;
}

Function Firework_DrawSelf()
{
	intRed = LookupHueColourR(This.fltHue);
	intGreen = LookupHueColourG(This.fltHue);
	intBlue = LookupHueColourB(This.fltHue);
	SetPenSize(4);
	SetPenColor(Program.GetRGB(intRed, intGreen, intBlue));
	Line(This.intX,This.intY,This.intX-This.intXspeed,This.intY-This.intYspeed);
}

Function Firework_MoveSelf(SpeedConstant)
{
	// This has had to be changed to allow for the speed constant
	// Note that technically the positions are no longer ints, because we are
	// modifying them by a fraction. Really they should all be flts (floats).
	This.intX += (This.intXspeed*fltSpeedConstant*10);
	This.intY += (This.intYspeed*fltSpeedConstant*10);
	This.intYspeed+=fltSpeedConstant*10;
	This.intFuseLength-=fltSpeedConstant*10;
}

Function Fireparticle(ParentFirework)
{	
	This.intX = ParentFirework.intX;
	This.intY = ParentFirework.intY;
	This.intXspeed = Math.Random(9)-4 + (ParentFirework.intXspeed/2);
	This.intYspeed = (Math.Random(9)-4) + (ParentFirework.intYspeed/2);
	This.fltHue = 3 * Math.Random();
	This.fltBrightness = (0.5 * Math.Random()) + 0.5;	
	This.DrawSelf = Fireparticle_DrawSelf;
	This.MoveSelf = Fireparticle_MoveSelf;
}

Function Fireparticle_DrawSelf()
{
	intRed = LookupHueColourR(This.fltHue);
	intGreen = LookupHueColourG(This.fltHue);
	intBlue = LookupHueColourB(This.fltHue);
	fltBright = This.fltBrightness;
	SetPenSize(1);
	SetPenColor(Program.GetRGB(intRed*fltBright,intGreen*fltBright,intBlue*fltBright));
	SetFillColor(Program.GetRGB(255 * fltBright, 255 * fltBright, 255 * fltBright));
	intSize = Math.Round(This.fltBrightness * 3) + 1;
	Ellipse(This.intX-intSize,This.intY-intSize,This.intX+intSize,This.intY+intSize);
}

Function Fireparticle_MoveSelf(SpeedConstant)
{
	// This too has had to be changed for the speed constant
	This.intX += (This.intXspeed*fltSpeedConstant*10);
	This.intY += (This.intYspeed*fltSpeedConstant*10);
	This.intYspeed+=fltSpeedConstant*10;
	// Some thought is required for the brightness speed constant
	// Instead of "*=0.9" we must use "1-(0.1*speedconstant*rate)" so that
	// a HIGHER speed constant means a HIGHER brightness multiplier so that
	// it fades SLOWER
	This.fltBrightness *= 1-(0.1*fltSpeedConstant*10);
	// This next bit is just bounce code so isn't affected by speed
	If(This.intY >= intScreenHeight)
	{
		This.intY = intScreenHeight - 1;
		This.intYspeed = -(This.intYspeed * 0.4);
	}
}
